Sandbox tokens only (devnet USDC has no value). Every signature is checked again by the next hop.
Offline: Bluetooth or camera QR
Online: HTTPS over cellular
Solana transaction

Airplane mode, zero bars
Payer iPhone Secure Enclave P-256 key that never leaves the phone. Face ID or passcode for every signature. Signs the 141-byte note.
Merchant iPhone Checks the note offline in the spec's order, reserves it against the allowance's offline limit, shows "Received, pending (sandbox)".
Android phone Android Keystore P-256 key behind a fingerprint or face check. Same note, same on-chain check.
Vultr VPS
Settlement API api.zerobars.us. Pays the fee, builds the transaction, returns a confirmation signed with its Ed25519 key. A refusal is never signed and never cached.
Solana devnet
secp256r1 precompile Solana's validators check the phone's P-256 signature over the exact note bytes. Low-S only.
loka_vault program Checks the allowance's cap, expiry, earmarks and a 256-bit serial bitmap. A reused serial fails with SerialUsed.
Vault One program-owned devnet USDC account. Allowances are locked here before anyone goes offline; merchants are credited from it.
What each hop checks
  • Payer phone: the owner's face or passcode before the key signs.
  • Merchant phone: every signature and the allowance's offline limit, with no internet.
  • Settlement API: the same checks again; it cannot forge or redirect a payment.
  • Solana: the signature, the serial, the cap and the expiry, on chain.
The note is 141 bytes; on the wire it carries a 64-byte low-S signature and the 33-byte public key (238 bytes). Layouts: protocol/PAYMENT-V1.md. HTTP: protocol/API-V1.md. Addresses: config/pins.json.
