# One filtered Cards deck

The default Cards entry on the existing four-game Play shelf now uses `UX/LOKA three-screen card game UI (1).png`: choose Two friends/A couple/A group (3–20 people), choose Clean/Drinking/Dirty, confirm age only for an unconfirmed restricted selection, then draw from one deck. There is no category-game library in this default flow. The deep-plum background, lavender card, mint Clean and coral Dirty controls use checkmarks as well as color. Filters stays in the footer beside Skip, below Next card; the bottom sheet edits a draft. Dismissal never changes applied filters or the current card.

Dirty requires self-declared 18+ and Drinking 21+, as requested. Cards uses native scrolling birthday wheels with inertial motion. A wheel selection is required before confirmation. Full, real dates are required; changing month or year clamps the day to a valid date, future dates cannot be selected, and age is checked against the exact birthday. Confirmed eligibility flags are stored locally in a separate namespace; birth dates are not stored or sent. An ineligible selection becomes unavailable for that view, with a Clean fallback. This is self-declaration, not verified identity or proof of age.

Catalog 3.2 preserves the 218 original IDs, prompt text and restrictions, and adds 76 authored prompts (294 total) with audience packs, stages and optional local name templates. `tags`, `requiresAdult` and `requiresDrinking` remain authoritative. Flirty/dirty prompts, consent dares and Fuck Marry Kill are conservatively tagged Dirty. Cards from games whose rules prescribe drinking, and alcohol/drinking prompts, require Drinking. A prompt may require both categories. Matching any tag is necessary, but all restrictions must also be enabled and eligible. Clean-only cannot draw restricted content. Tag assignments should receive editorial review before a public release.

Kotlin and Swift implement the same seeded SHA-256 shuffle ranking using existing platform implementations. This is deterministic deck ordering, not a cryptographic fairness or malicious-host guarantee. Next card and Skip each draw an unseen eligible ID; applying filters retains the shown set and immediately draws another unseen matching card. Exhaustion displays “You’ve finished this deck” with Shuffle again and Change filters. Shuffle again begins a new cycle and avoids putting the previous card first when another eligible card exists.

Before revealing the first card, Android and iOS begin with an empty card area and deal illustrated cards into a stack one at a time. The stack represents the whole eligible deck without rendering every prompt. Applying filters and Shuffle again replay the shuffle. Horizontal dragging follows the finger with tilt; short drags spring back, and distance or flick momentum commits one draw in either direction. Next/Skip remain available as button alternatives. Controls are locked during shuffle and throw, and animations send no network events. iOS Reduce Motion shortens the sequence and removes animated tilt; Android animations respect the system animation duration scale.

## Current network boundary and limitations

The newly requested filtered-deck flow currently runs on **one phone**, which can be shared by players. Its in-progress deck stays in memory and resets when that view is recreated. This flow sends no game events, birth date or catalog content over the network.

The existing Nearby multiplayer entry is retained separately. It still uses the previously implemented G2 accepted-round flow, bounded 2–4-device sessions and the existing encrypted LOKA transport. It does **not** synchronize this new deck's live filter edits or its full exhaustion/shuffle state. Its catalog eligibility now also excludes drinking-tagged content unless optional drinking is enabled, and the UI requires 21+ confirmation for that option. Legacy Quick Quiz still uses contacts. Ludo and Chess remain Coming soon.

Bringing this exact filtered-deck UX into shared nearby sessions remains required work: specify and review a new bounded state/snapshot format, negotiate its capability, authorize filter changes and age acceptance per participant, preserve shown IDs and proposal cancellation through reconnection, and validate compatibility and simultaneous chat. Do not silently map local filter changes into old G2 moves, truncate a full deck at the G2 24-action limit, or claim that existing G2 tests prove the new shared-deck behavior.

## Local names and turns

Version 0.6.62 collects a nonempty, distinct name for every local player before the first card or age confirmation. Names are trimmed, limited to 40 characters, and kept in memory for this Cards session; no names or birthday data are sent to the network. Nearby continues to use its existing authenticated participant roster. Increasing or decreasing the local player count requests the corresponding names before applying the draft. Dismissing names or age confirmation leaves the applied roster, turn, audience and card unchanged.

The current player’s name appears directly below the styled game heading, above the player-count label. Next, Skip and a completed swipe advance once to the next named player, wrapping around the roster. Opening rules, a cancelled filter edit and an incomplete swipe do not advance the turn. Applying a filter is a setup change rather than a completed player turn; reshuffling retains the next player.

The previous typed birthday editor has been replaced by native date wheels on Android and iOS. These wheels keep month/day/year valid together and provide animated scrolling without a keyboard. Full birthday dates remain transient, with existing local eligibility flags unchanged.

## Social Cards experience — version 0.6.65

The Play shelf labels Cards as 2–20 players. This describes people sharing one phone; Nearby retains its existing four-device policy, explained in its setup. Light-mode audience buttons and unselected categories use lavender surfaces and visible plum borders. Selected categories retain their mascot, fill and checkmark. Long names leave Game options reachable.

Setup adds All packs, Classic mix, New friends, Close friends, Couples, Family and Big parties. The five new packs contain 76 authored prompts; the original 218 IDs, text, modes, ranges and restrictions are unchanged. Family content is Clean-only. Group activities keep suitable player minimums and support up to 20; existing cards keep their editorial maximums. Couples prompts support exactly two people in couples mode. Pack filtering never bypasses audience, Dirty 18+ or Drinking 21+ checks. Loaders and catalog checks validate pack/stage metadata.

Quick round plans one turn per player; Longer round plans two; Open-ended continues until exhaustion. Setup displays matching and unseen counts and warns when a selected pack/category cannot fill the planned round. Exhaustion ends a round early without silently repeating questions. The deck prefers warm-up, playful and deeper stages as a round progresses, with the closest eligible stage as fallback. It never silently enables a category. Authored local question templates insert the current player and another roster member. Partner assignments rotate within longer rounds and across successive rounds so people do not always address the same person. Nearby continues showing readable generic text and using the existing protocol order.

Pass phone, then reveal is on by default. Handoff cards use the same illustrated card surface and show the next player's name; their actual question stays hidden until Reveal card. Upcoming cards are concealed in this mode. Shared-table play can turn handoffs off. The initial deal, completed swipe/Skip throw and native haptics remain; later reveals, undo and resume do not replay the initial shuffle. Round completion presents a brief visual transition and another-round/change-vibe/finish actions. Optional native card sounds start off. Existing Reduce Motion/system animation settings remain supported.

Names setup accepts comma- or line-separated paste lists, preserves spaces, and shows the number of names entered. All roster entries must be distinct, nonempty and at most 40 characters. Up to 2,000 pasted characters are accepted. The list remains editable field by field. Use names and Continue are both sized consistently with sheet actions. Game options permits roster edits without drawing a card, Undo last card, Pause game and Finish game.

Undo restores the previous prompt, exact seed/cycle/shown set, player turn, round progress, reveal state and partner rotation. It is a single-step undo. Filters and roster edits clear undo to avoid undoing across setup changes. Local snapshots hold the current frame and one previous frame, names, filters, pack and presentation settings; no answers, birthday or network messages are recorded. Saves are bounded to 64 KiB and resume within 24 hours, provided their full prompt-content fingerprint and age eligibility still match. Expired, malformed or changed-catalog saves are cleared when loaded. Finish removes the saved game. An interruption pauses the view; a returning or relaunched app resumes the exact game via Resume game.

Catalog 3.2 changes the exact-byte Nearby pack hash. Older catalog rounds cannot be resumed under the new pack. Their protected archives are left intact; both apps recognize a bounded, well-formed older PC2 pack header and permit a fresh engine/new round instead of disabling Cards. Malformed archives still fail the existing checks. Peer key validation and wire/admission/acknowledgement behavior are unchanged. Nearby players need matching catalog versions.

Validation and screenshots are recorded in [the social Cards results](../experiments/results/2026-10-06-cards-social-experience/README.md).
