# Untimed two-player game events v1

Application plaintext is `L1|G|1|kind|eventId|sessionId|packHash|expires|revision|value|ref` (ASCII; no newline; at most 1,024 bytes). IDs are canonical lowercase UUIDs; packHash is SHA-256 of the exact bundled Quick Quiz JSON bytes; integers are canonical unsigned decimal. `ref` is a UUID or `-`. Packet signatures authenticate the sender; membership uses the existing device fingerprint.

Kinds: C capability request, K compatible response, I invitation, J acceptance, S authoritative snapshot, M guest move, U host commit, A applied acknowledgment, R recovery request, E end/leave. Unknown versions/types are rejected. Existing packet versions and L1 chat content remain unchanged; old chat decoders reject G rather than rendering it as a message. Capability/pack response must match the outstanding request before the host sends I. This negotiates only game v1/rules v1/exact pack; no fallback is implied.

One host and one guest; explicit guest acceptance precedes S. Revision is the number of committed answers (0–10); question index equals revision. Host answers even indexes and guest odd indexes. Each correct answer adds one point to that player. M carries a chosen option (0–3), base revision and unique action ID. U carries next revision, chosen option and the originating action ID in ref. No arrival-order assumptions: stale exact commits ACK; gaps request S; conflicting actions reject. Host waits for applied confirmation before taking another turn; guest waits for U/S confirming its action.

S contains `phase;choice:actionId,...`, with `-` for an empty list; phase is active/ended. It carries the complete bounded committed prefix (at most ten actions), not assets, future answers or arbitrary scores. Recipients recompute scores. Prefix conflicts cannot be overwritten. Accepted peers can request S using R after interruption. J/R, commits and snapshots are acknowledged/retried through bounded ordinary-priority encrypted delivery; an A means the recipient persisted/accepted the event, not transport acceptance or chat delivery. A is a disposable response; duplicate events regenerate A with rate limiting. E is authorized leave/end and is retained until acknowledged or expired.

No automated host migration. Session lifetime is 24 hours, invitations/events 120 seconds. Session state/log/outbox persist separately from chat; expired outbox entries stop retrying and retain the committed log for recovery. Reopening requires Resume/synchronization before answering. Timed competition is unavailable. Existing LOKA route/carry policies alone decide admissible paths; games never select a radio.

Game sends set the existing signed outer packet expiry to the remaining event lifetime (maximum 120 seconds). Relays can expire obsolete game ciphertext without parsing it. Existing chat defaults and all packet byte layouts/signature inputs are unchanged.
